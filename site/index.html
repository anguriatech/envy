The commit is the distribution.

envy keeps your secrets in an encrypted local vault and shares them by committing sealed ciphertext straight into the repo. No SaaS, no tokens, no plaintext — and no network, because the binary has no network stack at all.

One vault. One artifact. Your repo is the delivery network.

envy replaces the shared .env file and the secrets channel in your chat app with a workflow your team already trusts: Git.

Encrypted vault~/.envy/vault.db · SQLCipher

Secrets live in a database encrypted at rest — file and values — with the master key in your OS keychain. Plaintext touches disk only when you explicitly ask for an import. Editing, listing, and diffing all work without it.

Sealed artifactenvy.enc · commit it

envy encrypt seals every environment into pure ciphertext — Argon2id-derived keys, fresh nonce per envelope — in one file you commit like any other. Teammates pull the repo and decrypt with the environment passphrase. The commit is the distribution.

Partial access, by designone passphrase per environment

Junior devs hold development; production stays sealed until someone with the passphrase runs the deploy. No ACL system to operate, no accounts to provision — the access boundary is the passphrase you chose per environment.

Headless for CIENVY_PASSPHRASE_PRODUCTION=…

Pipelines decrypt and upsert without prompts; envy diff and envy status return proper exit codes, so drift between the vault and the committed artifact breaks the build instead of the deploy.

Rotation with receiptsstaleness tracked per project

Configure a threshold per project; the inspector flags secrets past it. Rotate a passphrase in place — current, new, confirm — and re-seal in one flow, with the mismatch case recoverable instead of fatal.

Leak sweepenvy scan

Scan working trees for values that escaped the vault — before they escape into a public push.

Security you can verify, not vibes

The crypto surface is four modules of Rust. Every claim below is checkable in the repository — starting with the dependency list, where you will find no HTTP client, because envy never phones home.

  • Argon2id key derivation — 64 MiB memory, t=3, p=4: memory-hard on purpose
  • AES-256-GCM envelopes with a fresh nonce for every secret, every seal
  • SQLCipher vault — the whole database file encrypted at rest, metadata included
  • zeroize on drop — secret buffers scrubbed from memory when done
  • Constant-time base64 encoding on the artifact path
  • MIT licensed — read it, fork it, audit it; no telemetry exists to disable

Questions we expect

Why not sops?

sops is excellent — for config files. envy is built around the environment: a real vault with CRUD, sync-state tracking, and staleness flags, per-env passphrases so the intern holds development and never production, and a run/inject wrapper. sops decrypts to your editor; envy keeps values off disk unless you ask. Encrypting one YAML → sops. Managing team env vars → envy.

What stops someone brute-forcing the committed artifact?

Argon2id with 64 MiB of memory per derivation — memory-hard on purpose — under AES-256-GCM. The honest limit: passphrase strength is the system's strength. envy mitigates with per-environment separation (a leaked dev passphrase never exposes prod) and cheap rotation, but a weak passphrase on a committed artifact is still a weak system. We say so instead of hiding it.

Why is the master key in the OS keychain safe?

The same trust point as ssh-agent and browser-saved passwords. The alternative — a keyfile on disk — is strictly worse. Compromised machine beats every local-first tool, ours included; the committed artifact stays sealed regardless.

Does rotation give forward secrecy?

No, and we don't pretend otherwise: old ciphertext in Git history stays decryptable with the old passphrase. If a passphrase leaks, rotate it, re-seal, and rotate the external secret values too — envy tracks staleness so this gets flagged, but no tool can rotate your Stripe key for you.

Why trust a young project with my secrets?

Because the surface is small and local: no network dependency to audit, four crypto modules, MIT, and a design that assumes you will read it. Don't trust the star count — audit the code, or wait for the external review we want to fund. That's the honest answer for any young tool in this category.
